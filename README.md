# Bit Budget — information-channel measurement for reading signals

This repository measures how many bits about a text a reading signal (EEG
band power, eye-movement/gaze features, or both) supplies **beyond what a
frozen language model already predicts on its own**. It replaces the usual
"generate text and score it with BLEU" evaluation with a calibrated,
null-corrected information estimator, and then spends whatever information it
finds on a controlled candidate-selection task, evaluated as a communication
system (bits, information-transfer rate, risk–coverage curves).

It works on any dataset shaped like: a sequence of tokens, a per-token
context, and a per-token evidence vector (EEG features, gaze features, or
anything else time-aligned to the text). The shipped configuration targets
the ZuCo 1.0/2.0 EEG + eye-tracking reading corpus, but nothing in the
estimator is ZuCo-specific.

This package contains exactly the code that produced every number in the
paper — nothing else. No documentation drafts, no result files, no figures,
no unused/exploratory code paths.

## How it works

### 1. The frozen prior and the tilt

A causal language model (GPT-2-class, never fine-tuned) supplies a baseline
next-token distribution `p0(w | context)`. The evidence is not used to
generate text; instead it **tilts** that distribution multiplicatively:

```
p(v | evidence, context) = p0(v | context) * exp(gain * score(v, evidence)) / Z
```

`Z` is computed **exactly** over the full vocabulary (no top-k truncation),
so the tilt has a closed-form normalizer. `score(v, evidence)` is a linear
term plus a small nonlinear MLP applied to the prior's own token embeddings,
giving the evidence just enough capacity to bend the prior without
overfitting the vocabulary. If the evidence is zeroed or the gain is forced
to 0, the tilt collapses to a mathematical identity — the model reduces
exactly to the frozen prior (`cprd/model.py`, `cprd/objective.py`).

### 2. The evidence encoder

A small transformer (`cprd/encoder.py`) maps a short window of evidence
(t-1, t, t+1) to a low-dimensional, norm-bounded latent vector. Encoders are
provided for EEG-shaped input, gaze-shaped input, and a combined/fused input.
A structural rule enforced everywhere in the pipeline: **the fact that a
token was fixated/observed is never itself fed to the encoder as a feature**
— only the actual signal content is, so the model cannot solve the task by
exploiting *which* tokens have evidence rather than *what* the evidence says.

### 3. Measuring the information, not just training on it

The tilt above is trained contrastively (InfoNCE): for each token, the true
evidence must score higher than a batch of mismatched ("deranged") evidence
vectors drawn for the same token. At evaluation time the same construction
is turned into a proper variational lower bound on mutual information,
computed against two independent null constructions:

- **cross-sentence derangement** — evidence is paired with a different,
  length-matched, non-donor text, breaking text-specific correspondence
  while preserving coarse structure;
- **temporal roll** — evidence is shifted in time within the same
  session/subject, preserving subject-level statistics while destroying
  token alignment.

A channel is only called "informative" if the estimate is positive and
statistically significant against **both** nulls (`cprd/evaluate.py`,
`cprd/nulls.py`, `cprd/stats.py`).

### 4. Calibration before measurement

Before any real signal is touched, the same estimator is run on a synthetic
channel of exactly known information capacity (evidence generated by
construction to carry `b` bits about a token, sampled consistently with the
prior). This calibration step characterizes what the instrument can and
cannot detect, and produces an explicit **resolution floor**: below a
certain injected capacity, a null reading is reported as "below what this
instrument resolves," never as "zero bits" (`cprd/synth.py`,
`experiments/e1_estimator.py`, `experiments/e14_lowbit.py`).

### 5. Spending the bits: candidate selection

Once a channel's information is measured, a likelihood-ratio verifier scores
whole candidate sentences by summing per-token tilted log-likelihoods and
picks the best-scoring one from a distractor pool matched on length and
prior probability. Pool size is frozen from the measured bit rate *before*
looking at test data, and a text-only "no-evidence" attack is run against
every pool to catch cases where the pool itself is solvable without any
signal at all (`cprd/selector.py`, `cprd/pools.py`, `experiments/e3_selection.py`).

### 6. A gated, auditable pipeline

Every stage is a script under `experiments/` that reads a "gate" file
written by the previous stage and writes its own on completion
(`cprd/prereg.py`, `cprd/audit.py`). A failed gate is never silently patched:
downstream stages either skip, or proceed only through an explicit,
logged override (`experiments/override_gate.py`) that stamps every
resulting number as overridden. Every number a downstream analysis reports
must trace back to a ledger record.

Stages, in dependency order, with what in the paper each one produces:

| stage | script | what it does | paper result |
|---|---|---|---|
| E0 | `experiments/e0_build.py` | builds a text-clustered train/val/test split, extracts per-token EEG/gaze evidence, checks for text leakage | the dataset/split numbers (1,319 texts; 15,131/1,834/1,925 readings) |
| E1 | `experiments/e1_estimator.py` | calibrates the estimator on synthetic channels of known capacity | zero-anchor and lower-bound soundness checks |
| E2 | `experiments/e2_channel.py` | trains the encoder/tilt on one evidence channel, reports the calibrated information bound with both null tests | the 0.107 / 0.000 / 0.102 bits/token gaze/EEG/combined result, and the structure-only control (`--gaze-control structure_only`) |
| E3 | `experiments/e3_selection.py` | sweeps candidate-pool size, runs the no-evidence pool-validity attack, freezes the test pool size | the selection-accuracy-vs-N curve and the pool-validity attack numbers |
| E4 | `experiments/e4_system.py` | the one guarded pass over the held-out test set: accuracy, information-transfer rate, abstention/risk-coverage, and seven no-evidence control arms | the logged-test-evaluation table |
| E5 | `experiments/e5_attributes.py` | four-way task/session decoding, residualized on the other channel | the 0.821 / 0.482 balanced-accuracy result |
| E6 | `experiments/e6_seq2seq_baseline.py` | end-to-end generation baseline (verbatim architecture port) for comparison against the selection-based approach | the generation-baseline reproduction table |
| E7 | `experiments/e7_loso.py` | leave-one-subject-out generalization check | the 12-reader LOSO accuracy numbers |
| E8 | `experiments/e8_scaling.py` | training-data scaling curve | the 25%/50%/100%-of-training-data selection-accuracy numbers |
| E10 | `experiments/e10_breakdown.py` | per-subgroup (task/subject) breakdown of the channel measurement | the "positive estimates across all readers and all tasks" claim |
| E12 | `experiments/e12_sensitivity.py` | evaluation-gain sensitivity of the channel measurement (used for COFETT) | the COFETT evaluation-gain rows (Appendix) |

`experiments/report.py` renders a human-readable report from whatever gate
and ledger files exist; figures are regenerated either via
`experiments/make_figures.py` (called from `run_v2_followup.sh`) or directly
via `python -m cprd.pubfigs --out <dir>` — both read the same gate/ledger
files and produce the same plots.

## Installation

```bash
python3 -m venv .venv && ./.venv/bin/pip install --upgrade pip
./.venv/bin/pip install -r requirements.txt

# match the torch build to your driver, not the newest release:
nvidia-smi | grep "CUDA Version"
./.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cu121
```

The first run needs network access once, to pull the frozen prior and
BERTScore's backbone model from the HuggingFace hub; set `HF_HUB_OFFLINE=1`
afterward if the machine will be offline. NLTK's `wordnet`/`omw-1.4`
corpora are used by the text-metric utilities:
`python -c "import nltk; nltk.download('wordnet'); nltk.download('omw-1.4')"`.

## Preparing data

The pipeline expects, per reading session: tokenized text, a context id, and
a per-token evidence array of fixed width (plus an optional "observed" mask
for tokens with no evidence, e.g. unfixated words). `experiments/e0_build.py`
turns a directory of source recordings into this shape.

For the ZuCo corpus specifically, `tools/download_zuco.py` is a resumable
downloader:

```bash
python tools/download_zuco.py --dest <DATA> --tasks task1-SR,task2-NR,task2-NR-2.0,task3-TSR --workers 4
export ZUCO_PICKLES=<DATA>
export ZUCO_MATS=<DATA_MAT>     # optional, adds duration-based gaze features
```

## Running end-to-end

```bash
export HF_HUB_DISABLE_PROGRESS_BARS=1 TOKENIZERS_PARALLELISM=false

bash run_v2.sh                       # E1 calibration, then E2/E3/E4 for each evidence
                                      # channel (gaze / EEG / combined) -> runs_v2*/
bash run_v2_followup.sh              # gaze E4 seed replicates, E8 scaling curve, figures
bash run_additional_analyses.sh all  # E10 breakdown, instance-split leakage check, E7 LOSO,
                                      # structure-only gaze control, E5 attribute probe,
                                      # E6 generation baselines, E14 low-bit calibration
```

`run_additional_analyses.sh` also accepts a single stage name
(`breakdown`, `leakage`, `loso`, `struct`, `attributes`, `baselines`, `lowbit`)
to run one piece at a time.
Each stage writes a timestamped status line to
`<output-dir>/campaign_status.tsv` and a full log to
`<output-dir>/logs/<stage>.log`, and is safe to interrupt (`Ctrl-C`) and
re-launch.

To run a single stage by hand instead of through the wrapper scripts, call
its `experiments/e*.py` file directly — every stage is a standalone
`argparse` CLI; pass `--help` to see its flags.

## External check on COFETT

`cofett/` contains everything specific to the COFETT external check (Section 4.5 and its appendix):
the data adapter (EDF -> per-character 840-d features -> HDF5), a float32 copy of the Qwen2.5-0.5B
prior, the run script, and a smoke test.
The measurement itself runs the unchanged `cprd/` and `experiments/` code. See `cofett/README.md`.

```bash
bash cofett/download_cofett.sh <RAW>
bash cofett/run_cofett.sh <RAW> <WORK>
bash cofett/smoke_test.sh                 # quick check, no recordings needed
```

## External check on OneStop

`onestop/` contains the data adapter, run script and smoke test for the OneStop eye-tracking
corpus (gaze only). The measurement runs the unchanged `cprd/` and `experiments/` code with the
same gaze instrument as ZuCo. See `onestop/README.md`.

```bash
bash onestop/run_onestop.sh <IA_REPORT_CSV> <WORK>
bash onestop/smoke_test.sh                # quick check, no data needed
```

## Design invariants

These hold throughout the codebase:

- The language-model prior is frozen and never appears in any optimizer's
  parameter list.
- The tilt's normalizer is computed exactly over the full vocabulary.
- The "was this token observed" mask is never an encoder input feature.
- A failed pipeline gate is never hand-edited to pass; the only way past one
  is a logged, explicit override (`experiments/override_gate.py`) that marks
  every downstream number.
- The held-out test split is read through a single guarded-access function,
  once per hypothesis; any deviation from that is appended to a log file.

```

                             statistics, information-transfer-rate/abstention metrics,
                             text metrics, audit ledger, figure rendering

```
